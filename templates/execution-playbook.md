# 问题稿编写执行手册（新会话用法）

> 配合 `00-README.md` 使用：写作规则以 00-README 为准，本手册只回答"怎么开新对话、贴什么、怎么验收、怎么返修"。每篇问题稿一个新会话，打样稿先行、总述与附录最后。

## 0. 执行哲学（先读这段）

- **刚性**：事实纪律（三层标注、不虚构、口径一致）、双层产物（可口述导语＋按需支撑内容）、验收四问——必须执行。
- **弹性**：结构按问题需要组织，不要求固定板块齐全；研究顺序、叙事重点、详略自主；参考线索只是起点，可以推翻。
- **阻塞式异议**：对规则、结构、黄金样例有异议，或发现与简历/基线/已确认结果的冲突——**先停下来问用户，裁决后再动笔**；执行细节自主。
- **用户侧闭环**：验收时逐条裁决议题——成立就改规则，不成立说明原因；同一条异议多稿反复出现时，优先怀疑规则本身。

## 1. 总流程

1. 在项目工作目录打开新会话；粘贴 §3 对应问题稿的启动 prompt；
2. Agent 读规则与资料索引 → 自主研究、取舍、写稿 → 交稿附事实自查＋批判性自查；
3. 按验收四问读稿、试讲导语、裁决随稿议题；
4. 通过 → 贴 §6 定稿指令；有问题 → §5 返修模板。

会话中断：新会话贴同一 prompt，加一句"草稿已在 drafts/chapters/piece-X.md，先读现有内容继续完成"。

## 2. 编写顺序与素材绑定

| 顺序 | 产物 | 必读 packets | 可选素材 |
| --- | --- | --- | --- |
| 1 | `piece-{{slug}}.md`（**打样**＝最容易偏移的问题） | {{列表}} | {{……}} |
| {{2…N}} | {{其余问题稿}} | | |
| N+1 | `chapter-00-positioning.md`（总述，从问题稿成稿提炼） | 01～{{NN}}＋已验收问题稿 | — |
| N+2 | `appendix-comparisons.md`（汇总对比） | `01-fact-boundaries.md` 比较基准＋全部成稿 | — |

跨问题公共事实已冻结（01 单独成节），各稿直接取用，不必等前一篇成稿；总述与附录仍须在问题稿验收后动笔。

## 3. 启动 prompt（每稿复制一份；规则不内联，由 Agent 自行读文件）

```text
为 {{工作区}} 面试指导书写问题稿「{{问题全文}}」。

必读（按顺序）：
1. {{工作区}}/00-README.md —— 产物定义（导语＋按需支撑内容）、验收四问、黄金样例
2. {{工作区}}/01-fact-boundaries.md —— 术语、数字三档、禁用结论、公共事实底稿
3. {{工作区}}/03-定界承接.md —— 问题清单定界、事件归属、事实三层标注规则
4. {{工作区}}/packets/{{该稿 packets 列表}}
5. {{简历路径}} —— 对应主张句
可选素材（只取事实，不继承结构）：{{列表}}

产出：{{工作区}}/drafts/chapters/piece-{{slug}}.md
结构：导语（第一人称可口述，约 400～600 字参考）＋ 支撑内容（按问题需要从 00-README §4 板单选取，不要求齐全）。

参考线索（仅作起点，可推翻，交稿时说明实际选定重点及理由）：{{2～4 条}}

交稿时提交两部分自查：
A 事实自查：所引数字与限定语是否与 01、packet 一致；三层标注（记录事实/当时判断（可未知）/现在复盘）是否分清；无禁用结论；材料整理工作未混入研发经历。
B 批判性自查：本稿最薄弱的 1～2 处；对规则、样例、事实包的异议与建议（不要自行改动）。

边界：只写产出文件；不修改 00/01/03、packets、简历与业务代码；{{运行类禁令}}。packet 不足时按 01 §5 基线读源码核实并记录所读文件。

交互分级（阻塞式）：与简历/基线/已确认结果冲突，或对规则与结构有异议——先停下问我再动笔；研究顺序、表达等执行细节——自主。
```

总述变体（前置：问题稿已验收）：不用导语模板。①唯一完整 2～3 分钟讲稿（问题清单开篇）②各主张与问题的关系（每条一段白话：复用了什么、深挖看哪一篇）③总览级追问 3–5 个。附录变体（前置：同上）：①简历效果↔实现技术总表 ②选型汇总表（选了什么/放弃了什么/对方更优场景）③方法谱系总表 ④共性设计模式（注明出自哪稿）⑤概念链接索引。对成稿只汇总不新写事实；矛盾——先停下来问。

## 4. 验收（四问＋事实核查，每稿通用）

1. 能否直接回答面试官正在问的问题？（试讲导语；抽 2–3 条转换后的重点追问口答，对照追问要点）
2. 能否把任务约束、机制选择和实际观察连起来？
3. 能否说明选择的代价与现在的评价？
4. 是否准确区分已做工作、当时判断和后续建议？（三层标注抽查）
5. 事实核查：数字口径与 01/packet 一致；无禁用结论；候选思路均标"未验证建议"。

**稿特有验收点**：{{每稿 1 条，建区时按该问题的事实写，如"直接动机是否忠实（未倒写成完整论证）"}}

## 5. 返修模板（定点反馈，防止整篇重写）

```text
对 {{工作区}}/drafts/chapters/piece-X.md 做定点返修。只修改下面列出的问题，未提及的内容保持原样，不要整篇重写：

1. 位置【导语/支撑内容·某处】问题：（引用原句）期望：（要什么效果）

完成后逐条说明改动。返修点与其他内容冲突或暴露新问题——先停下说明，等我确认。
```

## 6. 定稿指令（验收通过后粘贴）

```text
本稿验收通过。两件事：
1. 更新 {{工作区}}/00-README.md 第 8 节进度表中本稿一行为「已验收 {{日期}}」，不改动其他任何内容。
2. 若本次验收采纳了会影响其他稿的新事实（源码核实结论、口径修正等），逐条列出「事实 + 受影响的稿与 packet」，由我决定写入 01-fact-boundaries 或对应 packet；不要自行修改这些文件。
```

## 7. 常见偏差速查

| 现象 | 处理 |
| --- | --- |
| 导语写成第三人称说明书或超长讲稿 | 返修：第一人称压缩至可口述导语 |
| 为"结构齐全"硬填不相关板块 | 返修：删去与问题无关的板块，按问题需要组织 |
| 当时动机记不清却补写成"我的判断" | 返修：改为"动机未记录"，判断放"现在复盘"层并给依据 |
| 设计评价写成因果定论 | 返修：改为"有依据的设计评价，不是确定根因" |
| 材料整理工作混入研发经历 | 返修：移入 packet 内部备注 |
| 数字无口径或超出事实包 | 返修：回链 01/packet，否则删除 |
| Agent 频繁中断问执行细节 | 提醒交互分级：只有事实冲突与结构异议阻塞，其余自主 |
| 交稿只有合规自查、没有批判内容 | 提醒补批判性自查；模板填充不是合格交稿 |
