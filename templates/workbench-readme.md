## 3. 口述层（每篇问题稿第一部分）

第一人称、句式完整、可直接口述的**导语**，按问题需要组织叙事（背景与问题、判断、行动、结果与边界、取舍——要素按问题取舍，不要求固定顺序或齐全）；约 400～600 字（1.5～2 分钟）——**篇幅为参考，不压迫每个问题使用同一结构**。完整讲稿只在总述章。

- 未解决的真实问题按"现象→判断→尝试→观察→下一步"如实收尾；记不清的当时动机保留未知，不补写。
- 代码符号每篇至多 3 个，首次出现括注一句作用；不放链接、不放 commit 号；不用生活化比喻。
- 支撑内容机制描述用第三人称。

## 4. 支撑内容（每篇问题稿第二部分）

**按问题需要选取**以下板块，不要求每篇齐全；深度服务于把问题讲清，不以条目数、字段级颗粒度为普遍要求：

- **关键机制详解**：问题涉及的机制落到实现（用到符号时首现紧跟一句作用说明）。
- **观察与数据**：支撑该问题的实验观察、数字（带口径）。
- **设计与评价**：选择的出发点、代价与不足、现在的评价——区分已做工作／当时判断／后续建议。
- **简历效果 ↔ 实现技术对照**：仅在问题直接承载简历主张时使用；无直接主张的素材域以所支撑的子主张作对照，不新增成绩。
- **高概率追问与要点**：从本问题论断自然引出＋定界真题转换后的重点追问；要点按 30～90 秒可口答密度组织。
- **与主流替代方案对比**：仅当问题本身是比较类问题时展开；谱系总表归宿在附录，对方以最强形态出场。

链接只出现在支撑内容；通用概念优先中文百科条目，其次官方一手文档，皆无则正文一句话界定。读者读完任一条目能说出"这个名字是干嘛的"；审计过程等内部工作不进正文。

## 6. 事实边界与验收

- 术语、数字三档（掌握／会估算／查阅即可）、禁用结论、公共事实底稿见 `01-fact-boundaries.md`；章节事实见 `packets/`；事实三层标注：记录事实／当时判断（可未知）／现在复盘（有依据）。
- 版本基线逐仓钉死（01 §5）；与简历或已确认结果冲突时交用户裁决，不编造。
- **验收四问**：
  1. 能否直接回答面试官正在问的问题？
  2. 能否把任务约束、机制选择和实际观察连起来？
  3. 能否说明选择的代价与现在的评价？
  4. 是否准确区分已做工作、当时判断和后续建议？
- 另加事实核查：数字与限定语和 01、对应 packet 一致，无禁用结论。

## 7. 写作流程

一问一任务：读本文件＋01＋03-定界承接＋该问绑定的 packets（archive 素材可选，只取事实）→ 产出 `drafts/chapters/piece-*.md` → 按验收四问＋试讲导语验收 → 定点返修。启动 prompt 与返修模板见 `02-execution-playbook.md`。

跨问题公共事实已冻结（01），问题稿依赖事实而非其他稿成稿；总述与附录在问题稿验收后动笔。**结构性/规则异议为阻塞式**：对规则、结构、样例有异议或发现事实冲突——先停下问用户，裁决后再动笔；执行细节自主。验收采纳的新事实按定稿指令汇总交接。

不做：阶段任务契约、verify 仪式、跨文件状态同步。Git 提交由用户决定；未经请求不暂存、提交或推送。
