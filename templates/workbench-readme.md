## 3. 口述层（每能力章第一部分）

第一人称、五段模板，句式完整、可直接口述：

1. **背景与问题**：当时卡在哪——现象与代价，不先堆架构。
2. **我的判断**：为什么这样选择——对比过什么、放弃了什么、依据是什么。
3. **具体行动**：亲手做了什么——按因果串成行动序列，不是功能清单。
4. **结果与复盘**：结果与边界——有数字讲数字并说明口径；没有数字讲验证方式与边界，不编数字。
5. **设计取舍、踩过的坑、怎么修的**：现象→误判→根因→修复→验证，选 1～2 个最有讲述价值的案例。

硬性标准：

- 篇幅 3～6 分钟（约 1000～1600 字）。
- 代码符号（函数/参数/常量名）每章至多 3 个，首次出现括注一句作用；其余用精确中文名。
- 不放链接、不放 commit 号。
- 支撑层的机制描述用第三人称（本项目/系统）。

## 4. 支撑层（每能力章第二部分）

四个固定板块：

1. **关键机制详解**：口述层每个论断落到实现。项目内符号（函数/类/参数/常量）可以使用，每个符号首次出现必须紧跟一句作用说明；无解释的符号视为违规。
2. **简历效果 ↔ 实现技术对照表**：简历每句主张在左，实现它的具体技术在右。
3. **与主流替代方案对比**：公平比较——说明本项目的选择、付出的代价、其他方案更优的场景，不弱化对手。每组对比覆盖该问题的主流方法谱系，不止"本项目 vs 单一对手"的二元对照；谱系起点见 `01-fact-boundaries.md` 对应节，可按章节事实与业界现状扩展；替代方案以最强形态出场，本项目在谱系中定位，并说明与相邻形态的正交或叠加关系。
4. **高概率追问与要点**：从口述层论断自然引出，给要点与方向，不写成逐字稿。

链接政策（链接只出现在支撑层与对照表，口述层纯文本）：

- 通用概念优先链中文百科/知识库条目（如 learnagent.wiki）；
- 无条目的概念链官方一手文档（规范站、厂商文档、核心库文档）；
- 两者皆无时正文一句话界定，不强行附链。

硬性标准：

- 读者读完任一条目，能说出"这个名字是干嘛的"。
- 版本兼容性审计、证据核查过程等内部工作内容不进正文，留在事实包。
